Deployment Notes

The university website is a static GitHub Pages frontend. The accepted instructional curriculum remains v16.3; runtime v16.3.6 adds the accepted Teaching Media content-completion overlay after the existing v16.3.5 layer. Student Progress continues to synchronize through the production Cloudflare Worker and D1 database.

Deployment verification:Open build-info.json from the deployed site. It should report courseRelease 16.3, runtimePatch 16.3.6, evidenceRevision 16.2, cloudSyncProtocol 2, build v16.3.6-teaching-media-final-pots-accepted-20260918, and releaseStatus accepted-31-of-31-standalone-pass. The build marker remains network-fetched rather than served from the offline cache.
Acceptance status:The v16.3.6 Teaching Media pathway passed the final 31-week standalone explanation audit: 31/31 PASS with zero BLOCKER and zero MATERIAL DEFECT results. Hands-on/mastery systems remain required.

v16.3.6 integration

The v16.3.6 release adds teaching-media-content-completion.js after teaching-media-self-reliance.js. Use the supplied learn.html and service-worker.js so load order and offline caching match the accepted runtime exactly. Keep the existing repository structure; do not create a wrapper folder.

No frontend build, Worker redeployment, D1 migration, progress reset, calendar re-import, or Cloud Sync change is required. All calendar identities, saved progress identities, assessments, lesson content, and Study Guide assignments remain protected.

Mobile use

The site remains responsive and includes an installable web-app manifest. Once hosted over HTTPS, Safari’s Add to Home Screen option can make Alfred University behave like a dedicated app.

The static site does not contain a master database password or conventional login credentials. When Cloud Sync is enabled, the browser stores the user's Worker URL and private Student Sync Key locally so progress can synchronize across devices.

Export Progress and keep the Recovery Key separately before major site maintenance. Keep the existing site address; a new domain is a new browser origin and also needs a Cloud Sync allowed origin. Do not clear browser site data as a normal refresh step.
