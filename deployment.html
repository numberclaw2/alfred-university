Site Administration · v16.3 curriculum / v16.3.2 runtime

Deployment Notes

The university website is a static GitHub Pages frontend. The v16.3 integrated Classroom is the instructional source of truth; the current runtime patch is v16.3.2. Student Progress can synchronize through the production Cloudflare Worker and D1 database.

Deployment verification:Open build-info.json from the deployed site. It should report courseRelease 16.3, runtimePatch 16.3.2, evidenceRevision 16.2, and cloudSyncProtocol 2. The build marker is network-fetched rather than served from the offline cache.

What to upload

If the repository already has v16.3.1, extract the v16.3.2 runtime hotfix ZIP and upload its files to the repository root beside index.html, replacing matching names and adding the new build marker/report. Do not upload the ZIP itself or create a wrapper folder. A clean install can still start from the complete v16.3 flat package. No frontend build, Worker redeployment, D1 migration, or progress reset is required.

All site navigation, the 31-week Classroom curriculum, calendar data, resources, Word/PDF documents, images, and the Apple Calendar file use relative links and are packaged together. The Progress Portal stores data locally first and can synchronize through https://alfred-university-sync.totallywill13.workers.dev.

Mobile use

The site is responsive and includes an installable web-app manifest. Once it is hosted over HTTPS, you can use Safari’s Add to Home Screen option to make Alfred University feel like a dedicated app.

The static site does not contain a master database password or conventional login credentials. When Cloud Sync is enabled, the browser stores the user's Worker URL and private Student Sync Key locally so that progress can synchronize across devices.

Export Progress and keep the Recovery Key separately before updating. Keep the existing site address; a new domain is a new browser origin and also needs a Cloud Sync allowed origin. Do not clear browser site data as a normal refresh step.
